## EL PROBLEMA
- Competencia Kaggle: labo-iii-2026-ba (Maestría Ciencia de Datos, Univ. Austral).
- Objetivo: predecir las toneladas (tn) vendidas de 780 productos en FEBRERO 2020
  (periodo 202002), con datos de sell-in hasta DICIEMBRE 2019. Es un salto t+2
  (de diciembre se predice febrero, salteando enero).
- Entregable: CSV con columnas product_id, tn (780 filas).
- MÉTRICA (verificada empíricamente, submit de ceros da 1.000): WAPE / Total
  Forecast Error = sum(|real - pred|) / sum(real). Ponderada por toneladas:
  los productos grandes dominan el score. Objetivo L1/absoluto, NO cuadrático.

## LECCIONES CLAVE (leer antes de proponer experimentos)
1. DIVERGENCIA LOCAL/LEADERBOARD (pasó 8+ veces): el backtest honesto
   (train 201712->201802 o multi-corte, eval feb-2019) NO rankea igual que
   Kaggle (feb-2020). Causa: cambio de régimen macro Argentina 2018->2019->2020.
   El backtest sirve para DESCARTAR desastres, NO para elegir el ganador fino.
   Optuna sobre la vara local EMPEORÓ el LB las 3 veces que se usó.
2. BLOAT: pasado ~el set de v11, agregar features casi siempre EMPEORA aunque
   suban el gain (gain alto != mejor score). El modelo tiene ~1050 productos
   reales; el presupuesto de complejidad se satura rápido. Auditar redundancia.
3. El OLS mágico NO admite enriquecimiento (v5_bis): con 182 filas, cada feature
   extra sube varianza. Su fuerza es la simplicidad. Las features nuevas van en
   el LGBM y se combinan con el OLS vía ENSAMBLE.
4. ENSAMBLE: OLS + LGBM con peso ~80/20 (OLS domina). El backtest sobrevalora
   al LGBM; en el LB conviene POCA dosis de LGBM. El 80/20 fue el ganador (0.228).
5. Nivel cliente-producto (pares): predicción directa agregada PIERDE (0.29).
   Como features agregadas a producto tampoco aporta (redundante con ncli_*).
6. cat3 (99 niveles) es mejor contexto de familia que cat4 (58 grupos).
